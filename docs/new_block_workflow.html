01 — The core idea

Train an inspector once, send them to every new field

The expensive work — manually annotating crowns, training the detector, validating it against a real manual count — happens once, on the pilot. Every block after that is just running that already-proven model on new imagery. That's the entire reason the pilot phase is worth the upfront time: it converts a one-time cost into a fast, repeatable step.

Done once — pilot only

Annotate, train, validate

Repeated — every new block

Register, run, deliver

New orthomosaic in → same model runs → geolocated inventory out. No annotation, no training, no manual review of the model itself.

04 — The one exception

When we'd actually touch the model again

Not the routine case If a new block shows something genuinely unfamiliar — a weed type, terrain, or lighting condition the pilot never saw — that specific pattern gets added to the training data and the model gets a targeted update. This is caught during the QC pass on each block's results. In the production run it happened for two patterns — dense mature canopy and newly planted palms were under-detected — so examples of both were annotated and the model retrained (the released checkpoint, oil_palm_crown-9). It's the exception; running the existing model is the rule.
05 — Common questions

FAQ

Do you need to re-annotate or retrain for every new block?

No — that's the whole point of the pilot phase. The model was built once and reused across all 25 production blocks; it was retrained only when rollout exposed the dense-canopy and young-palm misses described above.

What input does each new block need?

Just the RGB orthomosaic. DSM/DTM are a helpful bonus for extra quality-control, not required.

How long does a new block take to process?

Registering and running the model is fast — a matter of minutes for the detection step itself, since there's no annotation or training involved, just execution of the already-finished model.

What if the new areas look different from the pilot?

Every block's results get QC-reviewed. If something genuinely new shows up, that becomes a targeted training update — the exception, not something that stalls the rollout.
