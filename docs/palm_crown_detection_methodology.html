01 — What this actually is

Deep learning, not a rules-based script

This uses deep learning — a subset of machine learning built on convolutional neural networks (CNNs). Specifically, an object detector (not a classifier): it doesn't just say "this is a plantation," it finds every individual crown and draws a box around it with a confidence score. That distinction is why it can produce a countable inventory rather than a coverage estimate.

YOLO

"You Only Look Once" — a CNN architecture that scans an image once and predicts all object boxes + classes in a single pass. Built for real-time detection speed.

Transfer learning

The model starts from weights already trained on millions of general images, then gets fine-tuned on our hand-labelled crown examples (2,898 in the training split) — not trained from zero.

Object detection vs. classification

Classification: "does this image contain palms?" Detection: "here are the 14 individual crowns, each with a location." We need the latter.

02 — Why YOLO, specifically

Five reasons, not a default choice

01

Task fit — needs individual locations, which requires a detector, not a classifier or a segmentation model (segmentation was deliberately avoided as unneeded complexity unless overlapping crowns prove to be a real problem).

02

Inference speed at scale — tens of thousands of image tiles across 12,166.6 ha (26 blocks) need processing; YOLO is built for exactly that throughput.

03

Works with modest training data — transfer learning means a few thousand annotated crowns (4,041 on 435 tiles here) is enough; training from scratch would need far more.

04

Established in remote sensing — CNN object detection for tree/palm crown counting from UAV imagery is a published, proven technique.

05

Runs on the hardware on hand — a single consumer GPU, no cluster — fits the delivery timeline without added infrastructure cost.

03 — End-to-end pipeline

Orthomosaic in, geospatial inventory out

Orthomosaic in

One large georeferenced RGB GeoTIFF — 48,012 × 39,196 px at 2.13 cm/px for the pilot.

Tile

Cut into overlapping 1,280 px chips. Overlap (256 px) guarantees a crown on a tile boundary is still whole in a neighboring tile.

Annotate

Humans draw ground-truth boxes on a representative, stratified sample — dense/sparse palms, weeds, roads, bare soil.

Train

The model learns crown vs. background by adjusting its weights against the ground truth, over repeated passes (epochs), with early stopping once it plateaus.

Validate on unseen ground

Tested on tiles from a spatially separate part of the block — not random tiles mixed with training data — so the number reflects real generalization.

Infer at full scale

The frozen, trained model runs over every tile in the block.

Geo-reference

Each tile carries its pixel→UTM transform from the tiling step, so every detection converts back to real Easting/Northing.

De-duplicate

Overlapping tiles can detect the same physical palm twice; geometric matching keeps the single highest-confidence detection.

Centroid

Each final crown box's geometric center becomes that tree's point location.

Inventory out

Tree ID, Easting/Northing, confidence, crown geometry, block ID — a GeoPackage + CSV, opens directly in QGIS/ArcGIS.

Count

Total de-duplicated detections = the palm count for that area.

QC

Sample false positives/negatives; cross-check canopy height (CHM); compare against a manually-counted reference patch for a real accuracy figure.

04 — Scaling to new blocks

The model is trained once, reused everywhere

For every subsequent 300 ha block: tile → run the same frozen model → geo-reference → de-duplicate → centroids. No re-annotation, no re-training — just re-running two scripts against the new file. Retraining only happens if a block reveals a genuinely new failure pattern (an unfamiliar weed type, say) — the exception, not the routine.

05 — On the canopy-height (CHM) check

Height confirms plausibility — it doesn't confirm identity

Sampling the canopy height model (DSM − DTM) at the 1,226 crowns from the first pilot annotation batch gives this plantation's real, measured height range — not a textbook figure:

p5p25Medianp75p95Max
0.92 m1.95 m2.33 m 2.75 m3.81 m5.53 m

(Short for oil palm broadly — consistent with a young plantation rather than mature trees. Performance on tall, mature palms with heavily overlapping crowns has not been measured.)

The honest limit CHM measures height only, not shape. It reliably rejects things too short to be a real palm (a weed clump at 0.3 m). It cannot tell a young palm apart from a light pole or another tree species at the same height — height alone doesn't encode what an object looks like. That disambiguation is done primarily by the model's learned visual pattern (crown shape, texture, color from the RGB training data), with CHM as a secondary plausibility filter and human visual QC as the final backstop.
06 — Common questions

FAQ

Did you use AI or machine learning?

Yes — deep learning, specifically a convolutional neural network trained to detect oil palm crowns as objects.

What is YOLO and why that model?

A real-time object detection architecture. Chosen for task fit, inference speed at plantation scale, low training-data requirements via transfer learning, precedent in remote sensing, and it runs on the hardware available — see section 02.

How do you know the count is accurate?

On 79 test tiles from ground the model never trained on (716 hand-labelled palms), 84.5% of detections are real palms and 77.4% of palms are found. Counting the interior of each tile — the part a block run keeps once overlapping tiles are merged — the model counted 519 palms against 518 by hand. Details and per-tile numbers are in MODEL_CARD.md and evaluation/.

How does this handle the rest of the plantation?

The trained model is frozen and re-applied to each new block's orthomosaic — same pipeline, no re-training required in the normal case.
